Foundation · Layer stack · 2026-09-28

pkg/ is a stack, not a toolbox

Twelve packages, five layers, one direction of dependency. A package may import from the layer above it in this picture and never from the layer below — that rule is what keeps the services from forming a mesh.

The outbox is the load-bearing layer

  • pkg/outbox is imported by every service, and imports only pkg/obs
  • It is the one place where a transaction and an event are forced to agree
  • The sweeper, the relay and the consumer dedup all read the same table

Direction is the whole point

  • Handlers and services sit above pkg/store, never beside it
  • pkg/store and pkg/httpapi know nothing about each other
  • A cycle here would become a runtime cycle across three services

What each layer owns

  • Transport: httpapi, httpx — no business rules
  • Domain: models, validation, errs — no I/O
  • Foundation: config, obs, secrets — no domain types
