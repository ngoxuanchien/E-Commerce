Order lifecycle

One order moves from a reserved PENDING state to completion, with cancellation reachable from three earlier phases by a different actor each time.

Cancelling is always someone else's call

  • PENDING → CANCELLED is the system only: sweeper at 2 min, or a failed reservation.
  • PENDING_CONFIRMATION cancels by buyer or seller; CONFIRMED by seller alone.
  • Once shipping, the only way out is forward to COMPLETED.

The machine is a pure function

  • Transition(order, action, actor) → (event, error) — no I/O, fully testable.
  • Illegal moves short-circuit: 409 INVALID_STATE_TRANSITION, nothing written.
  • Optimistic lock on version; a lost race retries once, then 409.

Every transition writes twice

  • A order_status_history row and an OrderStatusChanged outbox message, same transaction.
  • Cancellations add OrderCancelled; catalog releases stock asynchronously.
  • Authorization: buyer must match buyer_id, seller seller_user_id — else 404, not 403.
