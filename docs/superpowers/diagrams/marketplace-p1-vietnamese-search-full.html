Searching "ao thun" finds "Áo thun"

Two converging paths: a stored unaccented search vector at write time, a ranked tsquery at read time.

Why the IMMUTABLE wrapper exists

  • Postgres unaccent is STABLE, not IMMUTABLE
  • search_vector is GENERATED ALWAYS AS (… ) STORED
  • Stored generated columns reject non-IMMUTABLE expressions outright
  • So vn_unaccent(text) wraps the extension call as IMMUTABLE

Index and query shape

  • setweight(to_tsvector('simple', vn_unaccent(name)),'A')
  • ‖ setweight(to_tsvector('simple', vn_unaccent(coalesce(description,''))),'B')
  • Query: websearch_to_tsquery('simple', vn_unaccent(q))
  • GIN on search_vector; q="ao thun" finds Áo thun

Browse rules

  • Only active products with ≥1 active SKU are listed
  • min_price is the lowest active-SKU price, written in the same tx
  • Category by slug includes children; shop by slug; price vs min_price
  • Keyset cursor = base64 JSON {sort_value, id}; limit 20, max 100
