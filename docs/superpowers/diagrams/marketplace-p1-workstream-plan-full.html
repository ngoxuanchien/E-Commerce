P1 workstream plan

WS0 fixes every interface before any feature code, then five workstreams run in parallel on one directory each and join at WS6.

Why the six Go modules exist

  • GO_MODULES = pkg gen services/gateway services/identity services/catalog services/order, joined by a go.work. Two workstreams can never produce conflicting go.mod edits, because each service is its own module.
  • WS0 owns pkg/ and gen/, so a parallel branch consumes the shared libraries as a contract instead of forking them.
  • Each track mocks only its neighbour: WS2 fakes Identity gRPC over bufconn, WS3 fakes Catalog gRPC, WS4 runs httptest upstreams with a JWKS stub, WS5 generates MSW handlers from the OpenAPI specs. WS1 needs no mock.
  • WS6 then runs against the real stack, and owns make seed and make e2e, which are placeholders until it lands.

Coordination and what stays open

  • Contract changes to api/, proto/ and pkg/ go through a dedicated PR to main; buf breaking blocks breaking changes and in-flight workstreams rebase afterwards.
  • WS6 starts once WS1–WS4 are merged. WS5 may land before or during WS6 — drawn as the dashed edge.
  • The spec fixes ordering and parallelism but no durations, so this graph carries no dates and is deliberately not a Gantt.
  • At HEAD the WS0 plan has Tasks 1–15 done and Task 16 on disk but uncommitted; Tasks 17–19 have not started.
