# WS4 Gateway Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the `services/gateway` skeleton into the single public entry point: route table, JWT verification via JWKS, coarse auth levels, identity header stripping and injection, CORS, per-IP rate limiting, body limit, request IDs, tracing and reverse proxying to identity/catalog/order.

**Architecture:** Small focused packages under `services/gateway/internal/` (`routes`, `auth`, `ratelimit`, `proxy`, `cors`) with no knowledge of each other except `auth → routes.Level`. `cmd/server` wires them into one `http.Handler` in the order fixed by WS4 §4. Per-route handlers (`auth.Middleware(level)` → upstream proxy) are precomputed at startup; a dispatcher matches the route table and calls the right handler. Every test uses `httptest` upstreams that echo received headers and a JWKS stub that serves a generated RSA key.

**Tech Stack:** Go 1.27.1, `net/http/httputil.ReverseProxy`, `github.com/golang-jwt/jwt/v5` v5.3.1, `golang.org/x/time/rate` (v0.16.0), `pkg/httpx`, `pkg/authctx`, `pkg/otelx`, `pkg/server`, `pkg/config`, `pkg/logx`, testify.

**Spec:** `docs/superpowers/specs/2026-09-28-marketplace-p1-ws4-gateway.md` (route/auth table: `docs/superpowers/specs/2026-09-28-marketplace-p1-ws0-foundation.md` §4; read-only).

## Global Constraints

- Only modify `services/gateway/` and this plan file. Never edit `api/`, `proto/`, `gen/`, `pkg/`, `deploy/`, other services, `go.work`, or `go.work.sum`. If a change there becomes necessary, stop and report it.
- Module path: `github.com/ngoxuanchien/e-commerce/services/gateway`; Go `1.27.1` (already pinned).
- Error body: `{"error":{"code","message","details"}}` via `httpx.WriteError`; codes `UNAUTHENTICATED` 401, `FORBIDDEN` 403, `NOT_FOUND` 404, `PAYLOAD_TOO_LARGE` 413, `RATE_LIMITED` 429, `INTERNAL` 500, `UPSTREAM_UNAVAILABLE` 503.
- Identity headers: `X-User-Id`, `X-User-Roles` (comma-separated). Always stripped from client requests.
- JWT: RS256 only, `kid` header required, `iss="identity"`, `exp` required, `exp`/`nbf` leeway 30 s, `sub` required.
- JWKS: load at startup with retry and backoff; `/readyz` 503 until loaded; refresh every 5 min; refresh on unknown `kid` at most once per 30 s.
- Rate limits per client IP: `/api/auth/login` and `/api/auth/register` 10 req/min; everything else 20 req/s, burst 40; 429 `RATE_LIMITED` + `Retry-After`.
- Body limit 1 MB (`httpx.MaxBodyBytes`) → 413 `PAYLOAD_TOO_LARGE`.
- Upstream connect/response-header timeout `UPSTREAM_TIMEOUT` (default 10s) → 503 `UPSTREAM_UNAVAILABLE`; upstream responses passed through untouched; path forwarded unchanged.
- Env: `IDENTITY_URL`, `CATALOG_URL`, `ORDER_URL`, `IDENTITY_JWKS_URL`, `CORS_ALLOWED_ORIGINS`, `UPSTREAM_TIMEOUT`, `TRUSTED_PROXIES` (empty = use remote addr).
- Access log: method, route prefix, status, latency, user id — never tokens, query strings or bodies.
- All code, comments, docs and commit messages in English. golangci-lint config: repo `.golangci.yml` (goimports local prefix `github.com/ngoxuanchien/e-commerce`).
- Tests: no real upstreams, no containers. `httptest` echo upstreams and a JWKS stub with a generated key pair.

## Review Focus

1. **Non-canonical paths** (trailing slash `/api/shops/me/`, percent-encoded `/api/shops/m%65`, `..`/`//`). These must never get a weaker auth level than the canonical path. Expected: the trailing slash gets the same (stricter) level, the encoded form is matched on the decoded path, and dot segments are redirected by `ServeMux` without being proxied. Pinned in Task 1 (`TestMatchNonCanonicalPathsKeepStricterLevel`) and Task 7 (`TestNonCanonicalPathsCannotDowngradeAuth`).
2. **Identity header variants** (lowercase `x-user-id`, `X_User_Id`, `X-USER-ROLES`, multiple values). All must be removed before proxying, because Go servers canonicalize names on the wire. Pinned in Task 4 (`TestStripIdentityHeaders`) and Task 7 (`TestClientCannotInjectIdentityHeaders`).
3. **Malformed `Authorization`** (`Basic …`, `Bearer ` with an empty token, two headers, lowercase `bearer`). Expected: 401 even on public routes; lowercase `bearer` is accepted. Pinned in Task 4 (`TestBearerToken`, `TestMiddlewareRejectsBadCredentialsOnPublicRoute`).
4. **JWKS trouble after the first load** (identity 500s, empty or garbage key set). Expected: cached keys are kept, tokens keep verifying and `/readyz` stays 200. Pinned in Task 3 (`TestRefreshFailureKeepsKeys`).
5. **Oversized chunked body** (no `Content-Length`). Expected: 413 `PAYLOAD_TOO_LARGE`, not 503. Pinned in Task 5 (`TestProxyMapsBodyLimitTo413`) and Task 7 (`TestBodyLimit`).

| `/api/categories` | ✓ | any | catalog | User |
| `/api/products` | ✓ | GET | catalog | Public |
| `/api/products` | ✓ | any | catalog | User |
| `/api/shops/me` | ✓ | any | catalog | Seller (stricter than GET\|PATCH so `me` is never treated as a slug) |
| `/api/shops/{slug}` | – | GET | catalog | Public |
| `/api/shops` | ✓ | any | catalog | User |
| `/api/seller/products`, `/api/seller/uploads` | ✓ | any | catalog | Seller |
