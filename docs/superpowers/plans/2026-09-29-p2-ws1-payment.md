# P2 WS1' payment-svc Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build payment-svc. It covers:
- payment attempts per checkout, idempotent, with per-order allocations;
- the provider port with FAKE, VNPay (sandbox) and Stripe (test mode) adapters;
- verified callbacks (VNPay IPN, Stripe webhook, FAKE webhook) with dedupe, plus return-URL handling;
- reconciliation, per-order and duplicate full refunds, and `CancelCheckoutPayments`;
- `payment.events` through the outbox.

**Architecture:** hexagonal, like the P1 services.
- `internal/domain` holds the pure rules: the `Apply` table, capture versus duplicate, the refund-due rule.
- `internal/app` holds the use cases behind ports: `Store`/`Tx`, `Provider`, `Orders`.
- Adapters are postgres (sqlc), fake, vnpay, stripe, order (gRPC client), grpc (server), kafka (consumer) and http.
- Callbacks are verified before parsing. Provider callbacks are hints, and `Query` is the truth, except for a verified FAKE event or VNPay IPN, which are authoritative for their own transaction.
- One transaction per state change: `provider_events` dedupe → `Apply` → capture/refund-due → outbox.

**Tech Stack:** Go 1.27 workspace, pgx v5 + sqlc v1.31.1, franz-go (`pkg/kafkax`), grpc (`gen/order/v1` client, `gen/payment/v1` server), `stripe-go` (latest major; pin it in go.mod), testcontainers (`pkg/testutil`), kin-openapi contract checks.

**Spec:** `docs/superpowers/specs/2026-09-29-marketplace-p2-ws1-payment.md` (binding) + ADR `docs/adr/0008-payment-provider-port-and-webhooks.md`.

Supporting documents:

- Overview `…-p2-overview.md` §1, §4.

## Global Constraints

- **Ownership.** Edit only `services/payment/**`, plus `go.work.sum` when stripe-go is added (WS0' §12: resolve conflicts with `go work sync`).
  - Never edit `api/`, `proto/`, `pkg/`, `deploy/`, `Makefile`, `.github/` or other services.
  - A needed change there is a finding for a WS0' follow-up PR, not an edit.
- **Money** is VND `int64` and never a float.
  - VNPay `vnp_Amount` is `amount × 100`.
  - Stripe VND is **zero-decimal**, so `unit_amount = amount`.
- **One capturing payment per checkout.** `amount = Σ total` over the checkout's `AWAITING_PAYMENT` orders. Allocations are one per order `{order_id, seller_user_id, amount = order total, commission_amount}`.
- **Event types and topics:**
  - types come from `pkg/event`: `PaymentSucceeded`, `PaymentFailed`, `PaymentRefunded`, `RefundFailed`;
  - topic `payment.events`, key `checkout_id`;
  - `PaymentSucceeded.allocations` is `[]` for a DUPLICATE;
  - `PaymentRefunded.order_id` is `null` for a duplicate refund;
  - `provider` is `vnpay|stripe|fake`.
- **Consumer group** `payment-svc` on `order.events`. `pkg/inbox` uses consumer name `payment-svc`.
  - A P1-era `OrderCancelled` (no `payment_method`) is treated as COD, so it is skipped: no row, no refund.
  - A COD cancellation (`payment_method = "COD"`) is also skipped: no row.
- **Idempotency-Key** comes from `pkg/idemkey`: scope `"payment"`, `staleBefore = now − claimStaleAfter` where `claimStaleAfter = 31 * time.Minute` (`PAYMENT_TIMEOUT` 30 m + 1 m margin, a constant because payment has no `PAYMENT_TIMEOUT` env). Keys are purged after 24 h.
- **Errors** use `pkg/httpx` codes.
  - Invalid state → 409 `INVALID_STATE_TRANSITION`, with `details.reason ∈ {COD_CHECKOUT, NOT_AWAITING_PAYMENT, DEADLINE_PASSED, ALREADY_PAID, BELOW_PROVIDER_MINIMUM}`.
  - Provider or order outage → 503 `UPSTREAM_UNAVAILABLE`.
  - Key reuse → 422 `IDEMPOTENCY_KEY_REUSED`.
  - Key in progress → 409 `CONFLICT`.
  - Anyone else's checkout or payment → 404.
- **FAKE wire format** (WS0' §12, WS1' §5.3): body `{"event_id","payment_id","outcome"}`. The header is `X-Fake-Signature: t=<unix>,v1=<hex HMAC-SHA256(secret, t + "." + rawBody)>`, with a 300 s tolerance. `outcome ∈ {succeed, fail, pending}`.
- **Env** (WS0' §8, already in compose):
  - `ORDER_GRPC_ADDR`, `PUBLIC_BASE_URL`, `PROVIDER_VNPAY`, `PROVIDER_STRIPE`;
  - `FAKE_WEBHOOK_URL`, `FAKE_WEBHOOK_SECRET`, `FAKE_WEBHOOK_DELAY`;
  - `RECONCILE_INTERVAL`, `RECONCILE_MIN_AGE`, `REFUND_MAX_ATTEMPTS`;
  - `VNPAY_TMN_CODE`, `VNPAY_HASH_SECRET`, `VNPAY_PAY_URL`, `VNPAY_API_URL`;
  - `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_MIN_AMOUNT`.
- **No real network in tests.** Adapters are tested against `httptest` stubs that compute real signatures and serve recorded JSON fixtures (`testdata/`).
  - The real-sandbox smoke test runs only with `-tags sandbox` **and** `PAYMENT_SANDBOX=1` plus credentials. It is documented in the README.
- **English everywhere.** The FAKE page's buttons are Vietnamese UI copy ("Thanh toán", "Thất bại").
- **Shared-volume rule.** Compose runs use `COMPOSE_PROJECT_NAME=p2ws1`. Never `down -v`. Leave no stack running.
- **TDD for every task.** `go test -race` and `../../bin/golangci-lint run ./...` stay clean in `services/payment`.

## Review Focus

1. **The same successful charge reported several times** (webhook, IPN, return URL, reconciler, duplicate delivery) produces exactly one `PaymentSucceeded` and never a second capture. Tasks 3, 5, 6, 7 and 10.
2. **A checkout paid twice.** Two attempts both succeed; for example, VNPay can't cancel, so the buyer pays the old tab. The second becomes `DUPLICATE`, with `allocations: []` and exactly one full refund (`order_id` null). Tasks 1, 3 and 10.
3. **A paid order cancelled before or after capture** refunds exactly that order's allocation once, in both arrival orders. A COD or P1-era `OrderCancelled` creates nothing. Task 8.
4. **A forged or stale callback changes nothing.** That covers a tampered body, a bad signature, a stale FAKE `t`, and a VNPay amount mismatch (`04`). No state change and no event. Tasks 4, 5, 6 and 7.
5. **An abandoned attempt still terminates.** With no callback at all, the reconciler moves the attempt to `SUCCEEDED`/`FAILED`/`EXPIRED` within `expires_at + 5 min + RECONCILE_INTERVAL`. `CancelCheckoutPayments` answers `NOT_PAID` only when no attempt can still succeed. Task 9.

```go
package domain

type Status string
const (
	StatusPending   Status = "PENDING"
	StatusSucceeded Status = "SUCCEEDED"
	StatusFailed    Status = "FAILED"
	StatusExpired   Status = "EXPIRED"
	StatusDuplicate Status = "DUPLICATE"
)
// Final reports SUCCEEDED/DUPLICATE: nothing changes them. FAILED/EXPIRED can still be overtaken by a provider success.
func (s Status) Final() bool
// Terminal reports every status other than PENDING (a payment shown as done to the buyer).
func (s Status) Terminal() bool

type ObservedState int
const (ObservedPending ObservedState = iota + 1; ObservedSucceeded; ObservedFailed; ObservedExpired)

type Observed struct {
	State         ObservedState
	Amount        int64  // VND as confirmed by the provider (checked only for Succeeded)
	ProviderTxnID string
	Reason        string
}

type Payment struct {
	ID, CheckoutID, BuyerID string
	Method, Provider        string
	Status                  Status
	Amount                  int64
	Captured                bool
	ProviderRef, ProviderTxnID, RedirectURL, FailureReason string
	ExpiresAt, CreatedAt, UpdatedAt time.Time
	Version                 int
}

type Effect int
const (
	EffectNone Effect = iota
	EffectFailed         // emit PaymentFailed
	EffectSucceeded      // run Capture
	EffectAmountMismatch // log error + metric; state unchanged
)

// Apply returns the payment after observing o, and the effect to carry out (spec §3 table).
func Apply(p Payment, o Observed) (Payment, Effect)

type CaptureDecision int
const (CaptureAsCapturing CaptureDecision = iota + 1; CaptureAsDuplicate)
func Capture(anotherCaptured bool) CaptureDecision

// RefundDue: a refund row must exist for an order's allocation exactly when the
// allocation's payment is captured AND the order is cancelled.
func RefundDue(paymentCaptured, orderCancelled bool) bool
```

The `Apply` table is exactly spec §3:

| current | observed | result |
|---|---|---|
| PENDING | pending | unchanged, EffectNone |
| PENDING | failed | FAILED, `FailureReason = o.Reason`, EffectFailed |
| PENDING | expired | EXPIRED, EffectNone |
| PENDING / FAILED / EXPIRED | succeeded, `o.Amount == p.Amount` | SUCCEEDED, `ProviderTxnID = o.ProviderTxnID`, `FailureReason = ""`, EffectSucceeded (the caller turns it into DUPLICATE when Capture says so) |
| PENDING / FAILED / EXPIRED | succeeded, amount differs | unchanged, EffectAmountMismatch |
| FAILED / EXPIRED | pending / failed / expired | unchanged, EffectNone |
| SUCCEEDED / DUPLICATE | anything | unchanged, EffectNone |

```go
// Provider is the port every adapter implements (spec §4).
type Provider interface {
	Name() string
	CreateSession(ctx context.Context, in SessionInput) (Session, error)
	Query(ctx context.Context, p domain.Payment) (domain.Observed, error)
	Cancel(ctx context.Context, p domain.Payment) (cancelled bool, err error)
	Refund(ctx context.Context, in RefundInput) (RefundObserved, error) // idempotent per RefundID
	QueryRefund(ctx context.Context, r Refund) (RefundObserved, error)
}
type SessionInput struct {
	PaymentID, CheckoutID string
	Amount                int64
	ExpiresAt             time.Time
	ReturnURL, Description, ClientIP string
}
type Session struct{ RedirectURL, ProviderRef string }
type RefundInput struct{ RefundID string; Payment domain.Payment; Amount int64 }
type RefundState int
const (RefundPending RefundState = iota + 1; RefundSucceeded; RefundFailed)
type RefundObserved struct{ State RefundState; ProviderRefundRef, Reason string }

// ErrProviderUnavailable wraps transport errors and 5xx answers from a provider.
var ErrProviderUnavailable = errors.New("provider unavailable")

type Providers struct{ /* byMethod, byName */ }
func NewProviders(forVNPay, forStripe Provider) Providers // either may be the FAKE adapter
func (p Providers) ForMethod(method string) (Provider, bool) // VNPAY | STRIPE
func (p Providers) ByName(name string) (Provider, bool)       // vnpay | stripe | fake

type Observer struct{ /* store, now, logger */ }
func NewObserver(store Store, now func() time.Time, logger *slog.Logger) *Observer
type Outcome struct{ Payment domain.Payment; Unchanged, AmountMismatch bool }

// ApplyObserved is the only way payment state changes after creation. One transaction:
//  1. eventKey != "" → InsertProviderEvent(provider, eventKey); duplicate → Outcome{Unchanged: true}.
//  2. LockCheckoutPayments(checkout of paymentID); use the locked row (fresh state).
//  3. domain.Apply. AmountMismatch → log.Error(payment_id, expected, got) and return, no write.
//  4. EffectFailed → UpdatePayment + Publish PaymentFailed{reason}.
//  5. EffectSucceeded → Capture(any other locked row captured):
//       capturing → Captured=true, SUCCEEDED, Publish PaymentSucceeded{allocations};
//                   for each allocation: IsCancelled(order) → InsertRefund(order, allocation amount);
//       duplicate → Status=DUPLICATE, Publish PaymentSucceeded{allocations: []},
//                   InsertRefund(order_id nil, full amount).
//  6. any other change (EXPIRED) → UpdatePayment only.
// Refund rows are PENDING with next_attempt_at = now; the refund worker executes them.
func (o *Observer) ApplyObserved(ctx context.Context, provider, eventKey, paymentID string, obs domain.Observed) (Outcome, error)
// Expire marks a still-PENDING payment EXPIRED (used by Create/Reconciler/Canceller after Cancel+Query found no success).
func (o *Observer) Expire(ctx context.Context, paymentID string) (domain.Payment, error)
```

Behaviour (spec §5.3):
- **CreateSession** inserts `fake_sessions{payment_id}` and returns `PUBLIC_BASE_URL/api/payments/fake/checkout/{id}` with `ProviderRef = "fake_" + paymentID`.
- **Query:** a recorded outcome → Succeeded/Failed; none → Pending, or Expired once `now ≥ ExpiresAt`.
- **Cancel:**
  - the session already has an outcome → `false`;
  - `hooks.cancel == unsupported` → `false`;
  - otherwise the session is marked expired (outcome `expired`) → `true`.
- **Refund and QueryRefund:** Succeeded with ref `fake_rf_<refundID>`, plus `refunded += amount`. With `hooks.refund == fail` → RefundFailed(`fake_refund_failed`).
- **Sender:**
  - after `WebhookDelay`, POST `Event` JSON with `X-Fake-Signature` to `WebhookURL`;
  - `duplicate` sends the same event twice;
  - `drop` sends nothing;
  - `stale_after` sends the real event, then a new event_id with outcome `pending`;
  - it runs in a goroutine on `context.WithoutCancel` and logs errors. The reconciler covers a lost delivery.
