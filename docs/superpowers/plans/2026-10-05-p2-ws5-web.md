# P2 WS5' web (online payment + seller wallet) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend `web/` with a payment-method picker, a redirect to the hosted payment page, a polling result page, pay-again for `AWAITING_PAYMENT` orders, and seller wallet and payout pages. Everything runs against MSW mocks.

**Architecture:**
- **Mock backend.** The MSW `MockDb` (`web/src/mocks/db.ts`) grows a payment state machine and a derived seller ledger (wallet, entries, payouts), so the UI is developed against the same rules the real services follow.
- **UI code.** It follows the existing layout:
  - typed hooks in `src/api/hooks/*`, built on `openapi-fetch` and TanStack Query;
  - feature folders under `src/features/*`;
  - routes in `src/routes/AppRoutes.tsx`.
- **Types.** Generated OpenAPI types only, aliased in `src/api/types.ts`.

**Tech Stack:** React 19, React Router, TanStack Query 5, openapi-fetch, openapi-msw/MSW 2, React Hook Form + Zod 4, Tailwind 4/shadcn, Vitest + Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-29-marketplace-p2-ws5-web.md` (plus `2026-09-29-marketplace-p2-overview.md`, WS0' §12). Contracts: `api/openapi/{order,payment,ledger}.yaml`.

- **Produces** the raw MSW route `POST */api/__mock/payments/:id/:outcome` → 204. It is untyped and uses `http` from `msw` directly, because it is not in the contract. An `outcome` other than `succeed`/`fail` → 400.
- **`createPayment` rules.** Each check below, in order, throws `MockError(409, 'INVALID_STATE_TRANSITION', …, { reason })` unless a different error is named:
  1. key missing or longer than 100 → validation `{ 'Idempotency-Key': … }`;
  2. `keys['payment:'+userId+':'+key]` exists → same `checkout_id` returns the current state of that payment; a different one → 422 `IDEMPOTENCY_KEY_REUSED`;
  3. no order of the buyer has that `checkout_id` → 404;
  4. the checkout's `payment_method` is `COD` → `COD_CHECKOUT`;
  5. any payment of the checkout is `SUCCEEDED` → `ALREADY_PAID`;

  7. `Date.now() >= deadline` → `DEADLINE_PASSED`;
  8. `amount = Σ total` of the AWAITING orders; `STRIPE` with `amount < STRIPE_MIN_AMOUNT` → `BELOW_PROVIDER_MINIMUM`.

  If the checks pass:
  - any `PENDING` payment of the checkout becomes `EXPIRED` with `redirect_url: null` (one open attempt);
  - the new payment is inserted:

    | Field | Value |
    |---|---|
    | `status` | `PENDING` |
    | `method` | the checkout's method |
    | `provider` | `'fake'` |
    | `redirect_url` | `` `${origin}/__mock/pay/${id}` ``, with origin from `globalThis.location?.origin ?? 'http://localhost'` |
    | `expires_at` | the deadline |
    | `failure_reason` | `null` |

- **`submitMockPayment` rules:**
  - an unknown id → 404;
  - a payment that isn't `PENDING` → no-op;
  - `fail` → `FAILED`, `failure_reason: 'mock_declined'`;
  - `succeed` when another payment of the checkout is already `SUCCEEDED` → `DUPLICATE`;
  - otherwise `SUCCEEDED`, and every `AWAITING_PAYMENT` order of the checkout becomes `PENDING_CONFIRMATION` with `payment_status: 'PAID'` and history `AWAITING_PAYMENT→PENDING_CONFIRMATION` by system;
  - a success where the orders were already `CANCELLED` (a late capture) sets those orders' `payment_status` to `'REFUNDED'`.

  Terminal payments get `redirect_url: null` and an updated `updated_at`.

  - `http.post('/api/payments')` → 201;
  - `http.get('/api/payments/{id}')` → 200;
  - the raw mock-submit route, with no auth (the FAKE page is public).
